## M9: eval gate (held-out test split, scored against dataset gold labels)

n = 185 held-out examples. Strong model (`groq-gpt-oss-120b`, its captured answers): **92.4%**. Gate: paired bootstrap (10,000 resamples, seed 7) of accuracy(distilled) - accuracy(strong); PASS iff the 95% CI lower bound is above -3 points. The margin was fixed before the first run and never changed.

| Version | Distilled accuracy | Valid outputs | Agreement with strong | Difference | 95% CI | Gate | Latency p50 / p95 |
|---|---|---|---|---|---|---|---|
| v1 | 89.2% | 97.8% | 90.8% | -3.2 pts | [-7.0, +0.0] | **FAIL** | 429 / 741 ms |
| v2 | 89.7% | 100.0% | 91.9% | -2.7 pts | [-6.5, +0.5] | **FAIL** | 372 / 643 ms |
| v3 | 92.4% | 100.0% | 93.0% | +0.0 pts | [-3.8, +3.8] | **FAIL** | 326 / 552 ms |

**The gate is underpowered at n = 185:** the 95% CI is up to ±3.8 points wide, more than the 3-point margin, so even a model that ties the strong model exactly (v3) can't pass. More held-out data is needed, not a looser margin.

The same test split was used for all 3 versions, so later versions had more looks at it (mild risk of adapting to the test set). Latency is llama.cpp on this laptop's CPU (4 threads).

### The gate was underpowered: one pre-committed re-run on more held-out data

v3 tied the strong model exactly on the original 185 examples, yet failed: with n = 185 the 95% CI is about ±3.8 points wide, so its lower bound can't clear -3 even for a perfect tie. That is a design flaw in the gate (no power calculation), not evidence about the model. The fix chosen *before* looking at any new result: replay every remaining unseen example from the same traffic, add them all as `test_extra` (captured after training, so no model has seen them), and run the gate **once** on the combined set with the **same 3-point margin**, accepting the outcome either way. No other re-runs, no margin change. The builder's filters still apply to the new examples, and most of the new traffic turned out to be out of scope (see Drift below), so far fewer examples were added than expected.

### Drift: new traffic the distilled model can't handle

The 23-label set comes from the traffic the model was trained on. Of the 800 requests captured up to the dataset build, 8 (1.0%) had a strong-model answer outside it. Of the **400 requests captured after the dataset was built, 362 (90.5%)** did: the later traffic is mostly intents the model has never seen (a side effect of the page-sampling bug, but exactly what real drift looks like).

**What this exposes in the design:** grammar-constrained decoding makes the distilled model always answer with one of its known labels, so the online *validity* check can never fire on out-of-scope inputs. The model would be confidently wrong and the rollback signal would stay silent. Validity is not correctness. Only comparison with the strong model catches it: shadow agreement, or a sampled share of canary/full traffic also sent to the strong model. That audit sample is the missing rollback input, and it is the next change to make.
