# Routing evaluation

_Generated by `uv run --extra router --group eval python -m eval.run` from the committed labelled data in `eval/data/`._

![Cost vs quality](cost_quality.svg)

## Setup
- **Prompts:** 1999 single-turn English prompts sampled from [Chatbot Arena](https://huggingface.co/datasets/lmarena-ai/arena-human-preference-55k) (Apache-2.0).
- **Cheap:** `or-llama-8b` (Llama 3.1 8B). **Strong:** `or-llama-70b` (Llama 3.3 70B). Both via OpenRouter, temperature 0, max 512 tokens.
- **Labels:** google/gemini-2.5-flash judges the two answers pairwise (order randomized per prompt). Label = 1 if the cheap answer wins or ties. Base rate: the cheap answer is good enough on **45.8%** of test prompts.
- **Judge consistency:** 1458/1998 (73%) of prompts got the same verdict with the answer order swapped; disagreements count as ties.
- **Split:** 1599 train / 400 test, stratified, seed 7. Thresholds for the quality settings come from out-of-fold predictions on train only.
- **Classifier:** logistic regression (C=0.3) on int8 bge-small embeddings of the first 128 tokens: the exact embedder the gateway serves.

## Results (held-out test set)

| Router | APGR ↑ | Strong calls for 50% of the gap (CPT50) ↓ | ... for 80% (CPT80) ↓ |
|---|---|---|---|
| Classifier (bge-small + logistic regression) | **0.537** | 44% | 79% |
| Heuristic (length, code, math) | **0.532** | 43% | 80% |
| Random | **0.484** | 53% | 81% |

Classifier minus heuristic APGR: **+0.005** (95% bootstrap CI -0.028 to +0.037, 1,000 resamples): the classifier does **not** significantly beat the heuristic baseline.

APGR = average share of the cheap→strong quality gap recovered across all call budgets (random routing = 0.5). CPT = share of requests sent to the strong model needed to recover that much of the gap (lower is better). Metric definitions follow RouteLLM (Ong et al., LMSYS 2024).

## Model selection (5-fold CV on the training split only)

Logistic regression was fixed in the plan. After the first test result, this study checked, using training data only, whether another model would have been better. None is by more than noise, so the simplest servable model stays.

| Candidate | Out-of-fold APGR | Log loss |
|---|---|---|
| Base rate (no model) | 0.500 | 0.6894 |
| Heuristic (length, code, math) | 0.524 | — |
| Logistic regression, embeddings (served) | 0.536 | 0.6801 |
| Logistic regression, embeddings + heuristic features | 0.520 | 0.9863 |
| MLP (64 hidden, early stopping) | 0.522 | 0.6860 |
| kNN (k=100, cosine) | 0.543 | 0.6787 |

## Interpretation

- **The prompt carries little signal about whether the 8B answer will match the 70B answer.** Every router recovers only a few points more of the quality gap than random routing, and the classifier's log loss is barely below the base rate's. The two models are the same family trained on similar data, so they tend to succeed and fail on the same prompts. The differences are idiosyncratic per answer, not predictable from the prompt.
- **Label noise caps what any router can learn:** 28% of verdicts flip when the answer order is swapped.
- This matches RouteLLM's finding that routers trained only on Chatbot Arena preferences perform close to random, and need augmented or in-domain labels to help.
- **What would move the result** (each costs a few dollars of labelling; the pipeline and caches support all three):
  1. a model pair with a larger quality gap (e.g. 8B vs a frontier model);
  2. more labels, plus in-domain data;
  3. graded (1-10) judge scores instead of pairwise ties.

Labelling cost (per-call `cost` reported by OpenRouter): generations $0.39, judge $1.41.
